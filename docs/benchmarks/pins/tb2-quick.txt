# Terminal-Bench 2.0 "tb2-quick" subset pin
#
# Format: one task ID per line. Commented (#) lines are EXCLUDED.
# Toggle by commenting/uncommenting. Uncomment ALL to run the full 89-task
# suite. See docs/benchmarks/02-terminalbench-canonical.md.
#
# This pin is consumed by Harbor via `--task-ids` (one flag per task, or a
# file the runner expands). The SAME pin state is used for BOTH the canonical
# Terminus 2 arm (doc 02) and the pi-adapter arm (doc 04) so they share a
# yardstick (decision: deliverables 2 and 4 use the same suite).
#
# Selection logic for the DEFAULT pin (12 tasks):
#   * Bias toward `difficulty = medium` and the shortest agent timeouts
#     (900s) to fit the 1-4h budget at ~56 tok/s on one RTX 3080, n=1.
#   * Spread across categories for a representative coding-experience signal.
#   * EXCLUDE tasks that are slow regardless of model skill (large builds,
#     VM installs, GPU-shaped ML, multi-thousand-second timeouts) — these
#     blow the budget on wall time alone and tell you little about the model.
#   * All TB2 tasks are gpus=0, so none are GPU-blocked on this host; the
#     constraint is purely wall-clock.
#
# agent_to below = the task's own agent timeout in seconds (from task.toml).
# It is the WORST CASE per task; a capable run finishes far sooner, a failing
# run can burn the whole budget. Doc 02 sets a runner-level per-task cap of
# 900s, which EQUALS the default pin's maximum task agent_to (all included
# tasks are 900 or 750) so it binds as a true ceiling. If you uncomment
# heavier tasks with larger agent_to, raise the runner cap to match or drop
# it and let the task's own agent_to bind — record the choice in the ledger.
#
# Calibrate before trusting totals: 12 tasks x up-to-15min = up-to-3h worst
# case at n=1. If calibration shows the model timing out on most tasks (likely
# for a 4-bit 35B-A3B local model), reduce the pin to ~8 tasks.
